# 阶段 1 · MVP（拉票 → 快照 → 整理需求 → AC 对照 → 出方案 → 选方案）执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 从 UI 触发，用开发者的 Chrome 读取 JIRA 上分配给我的 Ready for Dev 票，保存**只增不改的原始快照**，由 agent 整理出带**出处**的需求和 AC（可选人工审阅、编辑后自动做 **AC 偏移检查**），生成方案，开发者在 UI 上选定方案；全程写哈希链审计日志。

**架构：** pnpm monorepo。`server` 用 Hono 跑在 Node 24 上，直接运行 `.ts`；`node:sqlite` 存储；进程内任务队列编排。agent 统一通过 `Executor` 接口执行，默认实现调起本机已登录的 `claude` CLI（`-p` 无界面模式，JSON 流输出），并把仓库 `skills/<role>/SKILL.md` 作为该角色的系统提示词注入（skill 也可被开发者单独安装使用）。JIRA 通过 `TicketSource` 接口访问，默认实现是 `jira-browser` 角色经 claude-in-chrome 读页面。`web` 是 React + Vite，界面以 `design/` 下的 Stitch 设计稿为准。

**技术栈：** Node.js 24 LTS、TypeScript（只用可擦除语法）、pnpm workspaces、Hono + `@hono/node-server`、`node:sqlite`、zod 4、React 19 + Vite + Tailwind + shadcn/ui、`node:test`、Playwright。

**设计依据：**
- 设计文档：`docs/superpowers/specs/2026-11-06-slack-off-design.md`（重点 §5、§6、§9.6、§9.7、§9.9）
- 数据模型：`docs/ba/05-er.mmd`；状态机：`docs/ba/02-state-machine.mmd`；时序：`docs/ba/03-sequence-a-refine.mmd`
- UI：`design/screens/` + `design/code/`（01 Tickets、02 AC coverage、03 Requirements & AC、04 Original snapshot、05 Solutions、11 Settings）；`design/DESIGN.md` 为设计 token

## 全局约束

- Node `>=24`；server 和 shared 不构建，直接 `node src/main.ts`。`tsconfig` 开 `erasableSyntaxOnly`、`verbatimModuleSyntax`、`allowImportingTsExtensions`、`noEmit`、`strict`；相对 import 带 `.ts`；禁用 `enum` / `namespace` / 参数属性。
- 跨包 import 用 `@slackoff/shared`，其 `exports` 指向 `./src/index.ts`。
- 服务默认只监听 `127.0.0.1:4317`（开启远程访问后额外监听 Tailscale 地址，见任务 15）；web 开发端口 `5173`，`/api` 代理到 `4317`。
- 数据目录 `SLACKOFF_HOME`（默认 `~/.slackoff`）：`config.json`、`slackoff.db`、`runs/<runId>.jsonl`、`attachments/<sha256>`。
- 平台不读取、不保存 Claude 或 JIRA 凭证。
- 本阶段**不对 JIRA 做任何写操作**；`jira-update` skill 本阶段不实现。需求不清时只生成评论草稿。
- 默认 `autoRefine: false`、`reviewAcByDefault: false`、`concurrency: 1`。
- agent 输出必须通过 zod schema；失败重试 1 次，仍失败 → 票 `blocked` 并写明原因。
- 用户提示词只能**追加**在 skill 之后；硬性约束（schema、对外写需确认）由平台保证，不依赖提示词。
- 审计只增：`hash = sha256(prevHash + canonicalJson(event))`，`canonicalJson` = 键递归排序后 `JSON.stringify`；首条 `prevHash` 为 64 个 `0`。
- 快照只增不改：任何代码路径都不得 UPDATE / DELETE `ticket_snapshot*` 表。
- 界面文案英文，集中在 `packages/web/src/i18n/en.ts`（键值对），预留 `zh-CN`。
- 执行器名称在 UI 上显示为 "Claude Code (subscription)"，**不显示任何模型名**。

## 审阅重点

1. **本机没装 `claude` 或未登录** → 票 `blocked`，原因可见，不会卡在 `refining`。（任务 9）
2. **JIRA 登录过期**（浏览器 agent 看到登录页）→ `loginRequired: true`，UI 横幅提示登录；不得当成"0 张票"，不得修改任何票。（任务 10、11）
3. **agent 输出不合 schema** → 重试 1 次后 `blocked`，原始输出保留在 `runs/`。（任务 9）
4. **服务在 `refining` / `proposing` / `checking_drift` 期间重启** → 启动后自动重新入队。（任务 11）
5. **同一张票重复拉取 / 重复抓详情** → 票状态与已有需求、方案不被重置；内容没变不新建快照；变了就新建快照并链接上一版。（任务 6、7）
6. **开发者新增 AC 不写出处也不写理由** → 400，拒绝保存。（任务 12）
7. **偏移检查结果含丢失 / 无出处 / 矛盾** → 未"已知晓"（附说明）前不能继续出方案。（任务 11、12）
