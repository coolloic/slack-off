Problem Statement ¶1 – untouched

During high-concurrency checkout bursts, outbound calls to Stripe Tax API (/v1/tax/calculations) experience tail latencies exceeding the checkout service's synchronous timeout threshold (250ms SLA). When this happens, buyers receive a generic checkout failure error, abandoning high-value carts.

Requirements ¶2 – untouched

  • Deploy an in-memory cached tax rate matrix based on jurisdiction (country + state/province).
  • When Stripe Tax latency breaches 200ms or returns 5xx, transparently fall back to pre-calculated baseline tax tables.
  • Emit audit telemetry and alert FinOps via asynchronous ledger reconcile event.
edit_note description ¶3 · modified in v2
Updated by Anna Lindqvist 3h ago

The fallback handler must respond with HTTP 200 OK immediately return HTTP 202 Accepted and enqueue a background reconciliation job to prevent upstream retry storms when the Stripe Tax API exceeds the 200ms budget. All downstream invoices generated under fallback regime must carry the synthetic calculation marker tag.

Expected Outbound Fallback Event Schema schema/billing.tax.fallback.v2.json 
{
  "event": "tax.calculation.failed",
  "fallback_applied": true,
  "cached_rate_version": "2024-Q3-v1",
  "reconciliation_queue": "billing-tax-reconcile-p1",
  "retry_policy": {
    "max_backoff_ms": 5000,
    "dead_letter_target": "arn:aws:sqs:us-east-1:billing-tax-dlq"
  }
}
