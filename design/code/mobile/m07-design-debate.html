chevron_right Overview
Live

Adopts an in-memory distributed cache strategy fronted by Redis for Stripe webhook deduplication, retaining event keys within a 72-hour sliding window.

If the cache layer times out or becomes partitioned, the ingestion pipeline safely falls back to a PostgreSQL idempotency journal backed by atomic row locking.

Debate rounds

3 rounds completed
Round 1 Resolved
Blocking web Critic

Frontend replay timeouts under partition could submit repeated POST requests that saturate the worker thread pool before deduplication fires.

Designer • Response

Adding jitter backoff and optimistic state reconciliation prevents the browser client from firing immediate back-to-back bursts.

Round 2 Under Review
Blocking api Critic

Lock acquisition deadlock risk on database retry storms when multiple gateway replicas attempt journal table upserts simultaneously.

Designer • Response

Bounded distributed mutex hold time to strictly 250ms with jittered exponential backoff and fast fail to prevent pileups.

Round 3 Active Disagreement
Blocking api Critic

Unresolved migration ordering between api and worker services will cause transient schema mismatches during live rolling deploy.

Designer • Response

Propose DB schema additive change in release v1.4, followed by code switch, then deprecated column removal in v1.5.
